# Admin UI Flows

Course review covers initial submissions and the one sealed course update aggregate. All actual pending submissions remain visible with accurate badges; processed decisions have a separate history view. Inspect the complete proposal, including the authorized proposed 16:9 cover, before deciding. Approve/reject identifies the displayed request and opaque version; a stale tab receives 409 and must reload. Rejection requires a reason and preserves the editable proposal. The [replacement contract](../implementation/WORKFLOW_SUPERSESSION.md) replaces former fragmented review instructions.

System operations include storage/scanner/Gemini/worker/DB/backup health, alerts, class gradebook export and backup management. Sensitive actions retain reauthentication, exact phrase and reason policies. No impersonation action exists; live restore remains disabled by its separate operating contract.

TASK-090 preview uses the same read-only chapter/lesson tree and full lesson workspace as instructor preview. Proposed content and resource attach/detach operations are overlaid without mutating the original lesson. Preview alone performs no persistence or learner progress action. Approval/rejection is persisted with mandatory audit in one caller-owned transaction; concurrent reviewers serialize on the course and request rows. Invalid payloads, missing resources and invalid transitions return business errors. The queue refreshes from backend results after a decision, without requiring a page reload. Preview does not grant raw-video access to students or administrators without course-review permission.
