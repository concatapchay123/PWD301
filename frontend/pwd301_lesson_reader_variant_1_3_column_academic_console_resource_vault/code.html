1. Vấn đề của cấu trúc Monolithic trong Flask

Trong các ví dụ cơ bản lúc mới tiếp cận Python Flask, chúng ta thường khai báo toàn bộ route, model và cấu hình cơ sở dữ liệu bên trong một tệp tin duy nhất là app.py. Mô hình này rất thuận tiện cho quá trình học tập ban đầu hoặc xây dựng các công cụ nguyên mẫu (Proof-of-Concept) nhỏ.

Tuy nhiên, khi ứng dụng mở rộng lên hàng chục bảng dữ liệu và hàng trăm API endpoints, cách làm này bộc lộ ba nhược điểm chí mạng:

1. File phình to

app.py vượt quá hàng nghìn dòng, gây xung đột mã nguồn liên tục khi làm việc nhóm (merge conflict).

2. Circular Import

Module con import `app` từ app.py trong khi `app.py` lại import routes từ module con, dẫn đến treo runtime.

3. Khó Unit Test

Không thể cô lập từng module để chạy mock testing độc lập mà phải khởi động toàn bộ ứng dụng cồng kềnh.

2. Cơ chế Blueprint trong Flask

flask.Blueprint

Blueprint trong Flask là một cách để tổ chức một nhóm các view tương quan, bộ lọc template, static files và routing liên quan. Blueprint hoạt động tương tự như một ứng dụng thu nhỏ (mini-application) nhưng không trực tiếp khởi chạy độc lập mà được "đăng ký" (registered) vào ứng dụng chính.

@auth_bp.route('/login', methods=['POST'])
def login():
    data = request.get_json() or {}
    username = data.get('username')
    password = data.get('password')

3. Mô hình Application Factory Pattern

Thay vì tạo biến toàn cục app = Flask(__name__) ở phạm vi module, ta đóng gói quy trình tạo và cấu hình ứng dụng vào một hàm duy nhất thường được đặt tên là create_app(config_name).

# app/__init__.py
def create_app(config_class=DevelopmentConfig):
    app = Flask(__name__)
    app.config.from_object(config_class)

    # Khởi tạo các phần mở rộng an toàn
    db.init_app(app)
    migrate.init_app(app, db)

    # Đăng ký Blueprints
    from app.auth.routes import auth_bp
    from app.catalog.routes import catalog_bp
    app.register_blueprint(auth_bp)
    app.register_blueprint(catalog_bp)

    return app

Khi dùng Blueprint('auth', __name__), đối số thứ nhất là định danh duy nhất (namespace) dùng cho việc tra cứu hàm phân giải URL qua url_for('auth.login'). Đối số thứ hai __name__ báo cho Flask biết gốc thư mục để tự động định vị static files và template dành riêng cho module đó.
