## Edge Cases
| # | Feature | Input | Observed / Required Behavior |
|---|---------|-------|------------------------------|
| 1 | Timing Lock (BR-031) | Instructor attempts to modify `time_limit_minutes` while `assessment.status == 'PUBLISHED'` | Raises `AssessmentLockedError("Assessment timing (time_limit_minutes) is locked after publish.")`. In Web UI, flashes danger alert and prevents form submission. |
| 2 | Timing Lock (BR-031) | Instructor attempts to change `open_at` to a later or earlier date after publish | Raises `AssessmentLockedError("Assessment timing (open_at) is locked after publish.")`. DB trigger 51001 also throws if application layer is bypassed. |
| 3 | Timing Lock (BR-031) | Instructor extends `close_at` further into the future (e.g. from 2026-09-20 to 2026-09-25) after publish | Allowed! Both application service (`assessment_service.py:705`) and SQL trigger (`012_critical_invariant_triggers.sql:50`) explicitly permit forward extension of `close_at` to accommodate student emergencies. |
| 4 | Timing Lock (BR-031) | Instructor attempts to shorten `close_at` or set `close_at` to NULL after publish | Raises `AssessmentLockedError("close_at can only be extended forward after publish.")`. DB trigger 51007 blocks modification. |
| 5 | Structural Freeze (BR-030) | Instructor attempts to add a new question to assessment after `first_attempt_started_at` is stamped | Raises `AssessmentLockedError("Assessment questions cannot be modified after student attempt has started.")`. DB trigger 51002 prevents INSERT on `assessment_question_assignments`. |
| 6 | Structural Freeze (BR-030) | Instructor attempts to remove a question from assessment after `first_attempt_started_at` is stamped | Raises `AssessmentLockedError("Assessment questions cannot be removed after student attempt has started.")`. DB trigger 51002 prevents DELETE on `assessment_question_assignments`. |
| 7 | Structural Freeze (BR-030) | Instructor attempts to change assigned `points` for an existing question after `first_attempt_started_at` is stamped | Raises `AssessmentLockedError("Assessment question points cannot be modified after student attempt has started.")`. Prevents recalculation inconsistencies with ongoing attempts. |
| 8 | Structural Freeze (BR-030) | Instructor attempts to upload and import a PDF/DOCX to an assessment after `first_attempt_started_at` is stamped | Rejected at import creation / commit with `AssessmentLockedError`. Structural modifications are permanently sealed. |
| 9 | In-Place Question Edit | Instructor edits a question that is used in another published assessment or attempt | In-place edit of revision content is blocked. Service requires `change_reason` and automatically creates a new `QuestionRevision(change_type='EDIT')` while preserving historical revisions. |
| 10 | In-Place Question Edit | Instructor edits an unused question (never used in any published exam or attempt) | Content, choices, explanations, and accepted answers are updated directly in-place on the current `QuestionRevision` without creating revision clutter. |
| 11 | Question Type Lock | Instructor attempts to change `question_type` (e.g. SINGLE_CHOICE to MULTIPLE_CHOICE) after a student has answered it (`first_answered_at is not None`) | Raises `QuestionStateViolationError` ("Cannot change question_type... after it has been answered by a student"). DB trigger 51009 blocks even new revisions from altering `question_type`. |
| 12 | Choice Validation | SINGLE_CHOICE question submitted with 0 or >1 choice marked `is_correct=True` | Raises `QuestionValidationError("SINGLE_CHOICE questions must have exactly 1 correct answer (found X).")`. |
| 13 | Choice Validation | MULTIPLE_CHOICE question submitted with 0 choices marked `is_correct=True` | Raises `QuestionValidationError("MULTIPLE_CHOICE questions must have at least 1 correct answer.")`. |
| 14 | True/False Validation | TRUE_FALSE question submitted with 3 choices | Raises `QuestionValidationError("TRUE_FALSE questions must have exactly 2 choices.")`. |
| 15 | Short Answer Matching | SHORT_ANSWER submitted with duplicate accepted answers differing only by case (e.g. "Python" and "python") | Duplicates are automatically deduplicated in `seen_normalized` set; both map to normalized form `python`. |
| 16 | Document Import Binding | Document import uploaded directly from assessment builder | File uploaded and scanned; `DocumentImportJob` stores `draft_assessment_id=assessment.id`. When `commit_import_job` executes, all approved questions are added to QuestionBank AND automatically assigned to `assessment` via `assign_question`. |
| 17 | Fail-Closed File Import | User attempts to import an unscanned (PENDING) or quarantined/infected file | Raises `FileSecurityQuarantineError(403)`. Parser is never invoked on unsafe files. |
| 18 | Non-Structural Metadata Edit | Instructor edits assessment `description` or `title` after publish | Permitted, as `description` and `title` do not alter exam timing window, duration, question pool, or scoring weights. |

## 2. Logic Chain
1. *From* `ORIGINAL_REQUEST.md §R3` and `PROJECT.md § Interface Contracts § 3`, the requirement is to enable instructors to author questions directly from the exam page (Single Choice, Multiple Choice, True/False, Short Answer) with custom points and choices, perform in-place edits, and upload PDF/Word documents to automatically generate questions on the exam page.
2. *From* `01_BUSINESS_RULE_CATALOG.md` (`ASSESS-001`, `ASSESS-002`, `ASSESS-003`) and `06_NON_NEGOTIABLE_INVARIANTS.md` (Invariants 13 & 14), these operations must strictly adhere to the two-phase lock:
   - Timing Lock (publish phase): timing fields (`open_at`, `time_limit_minutes`, `attempt_limit`) cannot be changed after publish; `close_at` may only be extended forward.
   - Structural Freeze (attempt phase): question assignments, candidate pools, sections, blueprint rules, and points are locked permanently once `first_attempt_started_at` is recorded.
3. *From* inspecting `src/pwd301/services/import_service.py`, `draft_assessment_id` is an already-architected field in `document_import_jobs` (schema table `006_files_import.sql`), but was never wired in `create_import_job` or `commit_import_job`. Wiring `draft_assessment_id` in `import_service.py` allows the import pipeline to automatically populate the assessment upon commit.
4. *From* inspecting `src/pwd301/services/question_bank_service.py`, `create_question()` and `update_question()` already enforce all question validation (choice counts, single/multiple correct answers, bloom difficulties, unused in-place vs in-use revisioning, and answered type freeze).
5. *Therefore*, Milestone 3 requires:
   - Adding direct creation and edit routes (`/instructor/assessments/<assessment_id>/questions/create` and `/instructor/assessments/<assessment_id>/questions/<question_id>/edit`) that compose `question_bank_service` and `assessment_service`.
   - Adding assessment-level document import route (`/instructor/assessments/<assessment_id>/import`) and ensuring `create_import_job` and `commit_import_job` respect `draft_assessment_id`.
   - Updating `assessment_builder.html` to include "+ Tạo câu hỏi mới" and "Upload PDF/DOCX tạo đề tự động" modals with defensive UX locking when `structure_locked` or `timing_locked` is active.

## 3. Caveats
- No caveats regarding schema changes: `sql/004_assessment.sql` and `sql/006_files_import.sql` already define all necessary columns (`draft_assessment_id`, `points`, `source_type`). No database migration DDL change is required.
- Question type scope: while the schema supports `ESSAY`, `ORIGINAL_REQUEST §R3` explicitly specifies Single Choice, Multiple Choice, True/False, and Short Answer for in-page direct authoring.
- Regrading integration: if an instructor attempts to edit a question after attempts have started, the structural freeze blocks point changes and direct in-place edits. The instructor must use the existing Regrading/Correction workflow (`QuestionCorrection` and `/instructor/assessments/<id>/regrade`).

## 4. Conclusion
The specifications for Milestone 3 are authoritative, fully defined across System Specification documents, SQL triggers, and service invariants. The implementation requires three specific endpoint extensions in `instructor/routes.py`, draft assessment assignment integration in `import_service.py`, and interactive UI additions in `assessment_builder.html`, all strictly guarded by BR-030 (Invariant 14) and BR-031 (Invariant 13).
